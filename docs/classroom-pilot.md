# Interactive history beat classroom pilot

Status: prepared for use when classes resume

## Purpose

Validate whether interactive history beats improve participation and sustain attention without increasing teacher setup or disrupting the lesson.

The pilot tests product hypotheses. It does not diagnose students or measure individual ability.

## Privacy boundary

Do not record:

- student names;
- individual response histories;
- identifiable photos, audio, or video;
- personal or sensitive student information.

Use approximate class-level counts and anonymous notes.

Possible observable signals:

- side conversations unrelated to task;
- students waiting without a task;
- repeated teacher requests for attention;
- confusion about expected action;
- visible re-engagement after evidence, movement, or revision;
- discussion continuing after prompt ends.

Do not infer internal attention from one behavior alone.

### Delayed learning check

Attention capture is not learning evidence. When lesson structure allows, ask one short question in later lesson or exit check:

- recall central historical claim;
- identify strongest source detail;
- explain why answer changed or remained;
- apply same reasoning pattern to related case.

Record class-level result only. Do not create individual analytics for v1.

## Immediate teacher debrief

Ask after class. Keep this under five minutes.

1. Where did class attention rise?
2. Where did attention drop?
3. Which stage helped your teaching?
4. Which stage felt like product ceremony?
5. Did supplied wording sound natural when spoken?
6. Would you use this beat again without developer help?
7. What would you change before next use?

## Optional anonymous student pulse

Use only if teacher considers it appropriate. No account or personal data.

- Which clue changed your thinking most?
- Did you commit to an answer before discussion? Yes / no / unsure
- Did discussion help you notice evidence? Yes / no / unsure
- One word for pace: slow / right / rushed

Do not use enjoyment alone as evidence of learning or engagement.

## Decision record

After several uses, classify each mechanic:

- **Keep:** teacher can run independently, participation is broad, and evidence supports discussion.
- **Change:** core loop works, but pacing, wording, controls, or evidence need revision.
- **Drop:** mechanic repeatedly creates confusion, passive waiting, shallow guessing, exclusion, or excessive setup.

## Release gate

Do not claim that Toen. improves classroom attention or learning before pilot evidence exists.

Broader release requires:

- target teacher independently creates or imports one beat;
- target teacher runs one beat without developer intervention;
- no blocking classroom-control or projector issue remains;
- every first-wave mechanic has a keep, change, or drop decision;
- observed problems have severity and disposition;
- privacy boundary remains intact.
